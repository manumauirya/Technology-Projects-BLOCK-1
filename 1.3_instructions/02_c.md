## 🧱 Checkpoint 3 — C Program (commit: `c-basic`)
**Files**: `c/main.c`

```c
#include <stdio.h>
int main() {
    int x = 5;
    int y = x + 3;
    printf("Result: %d\n", y);
    return 0;
}
```
Compile, run, and inspect:
```bash
gcc main.c -o main
./main
objdump -d main | head -n 60 > main.disasm.head.txt
```
**Prompts (add to `journal/03_c.md`)**:
- Screenshot with the program output.
- Compare a few instructions from `main.disasm.head.txt` with the C code. What do you notice?

    The C code is easier to read, but the disassembly shows the same instructions in a lower-level form. For example, int x = 5 stores the value 5,
  and int y = x + 3 adds 3 to it. In the disassembly, these operations appear as machine-level instructions such as mov and add. The printf statement
   produces the output Result: 8. I noticed that one line of C code can become several assembly instructions, which the computer uses to execute the program.
